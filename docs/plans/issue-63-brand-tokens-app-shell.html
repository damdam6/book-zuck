1요약

PRD v1.2 §10 마일스톤 M0 — 모든 페이지가 올라탈 토대라 M1~M4보다 먼저 끝나야 한다. src/index.css의 토큰(포인트 색·손글씨 폰트·참여자 9색·브레이크포인트)을 보강하고, index.html에 구글 폰트를 추가하고, 제공된 브랜드 로고 SVG를 헤더에 적용하고, 5개 라우트가 공유하는 헤더/모바일 하단 탭바를 만든다. 마지막으로 두 스펙 문서의 hex 표기를 새 포인트 색에 맞춰 갱신한다.

2현황 분석

  • 토큰 — src/index.css:36의 --color-orange-500이 아직 구 값 #f83c00이다(PRD §4-3 OQ4는 #e8412f로 확정). --font-hand, participant-1..9, 반응형 브레이크포인트 토큰은 아직 존재하지 않는다.
  • 폰트 로딩 — index.html:15-18은 Work Sans·Plus Jakarta Sans·Padauk·Sankofa Display 4종만 구글 폰트 link로 로드한다. Nanum Pen Script가 없다.
  • 로고 — src/assets/brand/logo.svg(107×51, path 2개)는 이미 리포에 있지만 아무 곳에서도 import되지 않는다. fill="black"이 두 군데(offset 55708, 111169)이고 루트 <svg>의 fill="none"은 그대로 둬야 한다.
  • 헤더 — src/components/common/TheHeader.tsx:23는 로고 자리에 텍스트 "로고" placeholder만 있고 nav·활성 상태·모바일 탭바가 전혀 없다.
  • ProfileModal — src/components/Modal/ProfileModal.tsx:31-33의 "마이페이지" 버튼에 onClick이 없어 미연결 상태다(이슈에도 명시).
  • 인증 갱신 — src/hooks/useAuth.ts:13은 이미 supabase.auth.onAuthStateChange를 구독해 session state를 갱신하고 TheHeader는 이 훅을 그대로 소비한다. 완료 조건의 "로그인/로그아웃 후 헤더 즉시 갱신"은 구조적으로 이미 충족되어 있다 — 리라이트 중 이 구독 방식만 유지하면 된다.
  • 페이지 5곳 모두 헤더를 개별 호출 — HomePage·BookshelfPage· BookAgendaPage·AgendaNewPage·MyPage가 page-based-folder-structure 스펙 컨벤션대로 각자 <TheHeader />를 최상단에서 호출한다(예: src/pages/Home/HomePage.tsx:8). 즉 TheHeader 컴포넌트 자체만 고치면 5개 페이지 파일은 건드리지 않아도 자동 반영된다.
  • 스펙 문서 — docs/specs/design-tokens/spec.md에 #F83C00이 4곳(line 55, 61, 63, 168), docs/specs/book-agenda-view/spec.md에 2곳(line 82 ParticipantAvatar 선택 링, line 103 LikeButton)이 있다. 이슈 체크리스트는 "선택 링" 표기만 명시하지만 두 줄 다 같은 point 토큰을 가리키므로 함께 갱신하지 않으면 design-tokens 스펙이 이미 경고한 near-duplicate hex 문제가 재발한다.
  • 환경 — 이 워크트리에는 node_modules가 아직 설치돼 있지 않다(Tailwind v4.2.2, SVGR 플러그인은 미설치). eslint.config.js에 jsx-a11y 플러그인이 없어 dangerouslySetInnerHTML 사용 자체는 린트 이슈를 일으키지 않는다.

3설계

  • 브레이크포인트 토큰 — PRD §4-5의 5단계 중 4개를 Tailwind v4 @theme의 --breakpoint-*로 등록한다: --breakpoint-compact: 720px, --breakpoint-desktop: 1100px, --breakpoint-wide: 1200px. "mobile <720"은 별도 토큰을 만들지 않고 Tailwind v4가 --breakpoint-compact로부터 자동 생성하는 max-compact: variant((max-width: 719.98px))로 표현한다 — 중복 토큰을 피하는 선택. "max 1440"은 반응형 분기점이 아니라 컨테이너 상한이므로 breakpoint가 아닌 별도 폭 토큰 --width-shell: 1440px로 등록한다.
  • 로고 — 원본 asset logo.svg의 fill="black" 2곳을 파일에서 직접 fill="currentColor"로 바꾼다(PRD §4-1 문구 그대로). 컴포넌트에서는 Vite 내장 ?raw import(추가 의존성 불필요)로 SVG 마크업 문자열을 가져와 인라인 렌더링한다. <img src>로 쓰면 currentColor가 항상 검정으로 고정돼 "검정 이외 맥락에서도 쓰기" 요구사항을 satisfy 못하므로 인라인이 필수다. 새 컴포넌트 src/components/common/BrandLogo.tsx에 role="img" aria-label="북적북적"로 접근성을 보강한다.
  • 공통 셸 — TheHeader를 전면 리라이트해 데스크톱 헤더(로고+nav+로그인/아바타)와 모바일 하단 탭바를 한 컴포넌트가 함께 반환하게 한다. 탭바는 position: fixed이므로 DOM 순서와 무관하게 항상 뷰포트 하단에 그려진다 — 5개 페이지 파일을 건드리지 않고 TheHeader 한 곳만 고쳐도 모든 라우트에 전파된다. 활성 상태는 useLocation() 경로 prefix로 판별(/→홈, /bookshelf 또는 /books/*→책장, /my→마이).
  • 모바일 탭바 하단 여백 — PRD가 요구하는 "본문 padding-bottom:64px"은 5개 페이지의 <main>을 각각 고치는 대신 src/index.css에 @media (max-width: 719px) { body { padding-bottom: 64px; } } 한 줄을 추가해 전역 해결한다(대안이었던 "페이지별 main 클래스 수정"은 5파일 중복이라 기각).
  • ProfileModal 마이페이지 버튼 — useNavigate()로 /my 이동을 연결하고, TheHeader가 내려주는 onNavigate 콜백으로 드롭다운을 닫는다.
  • 참여자 9색 — @theme에 --color-participant-1부터 -9까지 등록한다. 기존 팔레트 값은 var(--color-coral-300) 등으로 참조하고, 이슈가 명시한 신규 hex 2개(#FAF4B0, #FFB5B5)는 재사용 브랜드 팔레트가 아닌 참여자 전용 단발 색이라 별도 색이름을 만들지 않고 participant-7/ participant-9 리터럴로 등록한다. 소비 컴포넌트(ParticipantAvatar)는 book-agenda-view 스펙 소관이라 이번 범위 밖 — 토큰만 선등록한다.

4작업 단계

  1. ✅ 토큰 보강 — --color-orange-500 값을 #f83c00→#e8412f로 교체, --font-hand: "Nanum Pen Script", cursive 추가, --color-participant-1..9 등록, --breakpoint-compact/desktop/wide + --width-shell: 1440px 추가, 모바일 탭바용 body padding-bottom 미디어쿼리 추가. src/index.css 참고: participant-2..9는 아직 소비 컴포넌트가 없어 Tailwind v4가 production 빌드에서 미사용 유틸을 tree-shaking함 — @theme 소스 등록은 완료, 빌드 산출물엔 실사용 시(M1+) 나타남. 정상 동작.
  2. ✅ 구글 폰트 — 기존 <link>의 family= 쿼리에 Nanum+Pen+Script를 병합(display=swap 유지, 폴백은 CSS --font-hand가 담당). index.html
  3. ✅ 로고 asset 수정 — fill="black" 2곳을 fill="currentColor"로 교체 (루트 fill="none"은 유지). src/assets/brand/logo.svg
  4. ✅ BrandLogo 컴포넌트 신설 — logo.svg?raw import 후 dangerouslySetInnerHTML로 인라인, className prop으로 크기/색 제어, role="img" aria-label="북적북적". src/components/common/BrandLogo.tsx(신규)
  5. ✅ TheHeader 전면 리라이트 — 좌측 로고(Link to="/") + nav(책장/마이페이지, 활성 시 point 색+2px 밑줄) + 로그인 버튼(검정, r4, 최소높이 44)/로그인 상태 아바타+이름 + ProfileModal 드롭다운. 같은 컴포넌트가 모바일 하단 탭바(홈/책장/마이, 높이 64, --font-hand 28px + 점 인디케이터, safe-area 패딩)도 함께 반환. 컨테이너 최대폭은 --width-shell. src/components/common/TheHeader.tsx 구현 시 확정: nav 표시/숨김은 PRD 반응형 표(§4-5)를 따라 compact: (≥720px) 기준으로 전환(하드 "desktop"(≥1100px) 기준이 아님) — 이슈 완료 조건의 "720px 미만" 문구와 정확히 일치. 로그인 버튼/아바타는 모바일에서도 계속 보이고, nav 링크(책장/마이페이지)만 숨겨짐 (PRD §4-5 "헤더 nav 숨김"이 문자 그대로 nav만 가리킴). Playwright로 400px/1280px 양쪽 확인 완료.
  6. ✅ ProfileModal 마이페이지 버튼 연결 — useNavigate()로 /my 이동, 부모로부터 받은 닫힘 콜백 호출. src/components/Modal/ProfileModal.tsx, src/components/common/TheHeader.tsx
  7. ✅ design-tokens 스펙 갱신 — 폰트 표(§1)에 Nanum Pen Script/--font-hand 6번째 행 추가, #F83C00 4곳을 #E8412F로 교체. docs/specs/design-tokens/spec.md
  8. ✅ book-agenda-view 스펙 갱신 — 선택 링(§B5) 5px #F83C00→ 5px #E8412F, 같은 이유로 LikeButton(§D4)의 #F83C00도 함께 교체. docs/specs/book-agenda-view/spec.md
  9. ✅ 검증 — pnpm install(node_modules 없는 워크트리라 최초 1회 필요) → pnpm build → pnpm lint → pnpm dev + Playwright(headless Chromium, 임시 npx 설치·프로젝트 의존성에는 미포함)로 5라우트·모바일 탭바·콘솔 에러 확인. package.json(스크립트 변경 없음, 실행만)

5리스크

리스크영향완화책
로고를 dangerouslySetInnerHTML로 인라인 일반적이지 않은 패턴, 리뷰 시 XSS 우려 제기 가능 소스가 빌드 타임에 번들되는 리포 내 정적 파일(사용자 입력 아님)임을 컴포넌트에 짧은 주석으로 명시
신규 --breakpoint-* 토큰명이 Tailwind 기본 sm/md/lg와 겹치지 않는지 겹치면 기존 유틸리티가 깨짐 이름을 compact/desktop/wide로 분리(기본값과 겹치지 않음), pnpm build로 유틸 클래스 생성 여부 확인
워크트리에 node_modules 미설치 pnpm build/lint 실행 전 설치가 선행돼야 함 검증 스텝 맨 앞에 pnpm install 배치
participant-1..9 토큰은 소비 컴포넌트가 아직 없음 토큰만 등록되고 시각적으로 확인할 화면이 없음 pnpm build로 유틸리티 클래스 생성만 확인, 실사용 검증은 M1+ book-agenda-view 구현에서

6테스트 계획

  • pnpm install && pnpm build(tsc -b && vite build) 통과 확인.
  • pnpm lint 통과 확인.
  • pnpm dev 실행 후 /, /bookshelf, /books/1/agenda, /agenda/new, /my 5개 라우트 모두 동일한 헤더가 뜨는지, 로고 클릭 시 /로 이동하는지 확인.
  • 브라우저 폭을 720px 미만으로 줄여 nav가 사라지고 하단 탭바가 뜨는지, 현재 라우트에 해당하는 탭이 point 색(#E8412F)으로 표시되는지 확인.
  • 구글 로그인/로그아웃을 실제로 수행해 헤더가 즉시 리렌더(로그인 버튼 ↔ 아바타+이름 전환)되는지 회귀 확인(기존 onAuthStateChange 구독 경로 유지 검증).
  • ProfileModal에서 "마이페이지" 클릭 → /my 이동 + 모달 닫힘 확인.
  • DevTools에서 --color-orange-500 계산값이 #e8412f인지, Network 탭에서 Nanum Pen Script 폰트 요청이 200으로 로드되는지 확인.

7완료 조건

  • ✅ 5개 라우트 모두 동일한 헤더가 뜨고 로고 클릭 시 홈으로 이동한다. — Playwright로 5라우트 전부 헤더 동일성 + 로고 클릭 확인.
  • ✅ 720px 미만에서 nav가 사라지고 탭바가 뜨며 현재 탭이 point 색(#E8412F)으로 표시된다. — 400px 뷰포트에서 확인, 탭 클릭 시 활성 색 전환도 확인.
  • ✅ 로그인/로그아웃 후 헤더가 즉시 갱신된다(onAuthStateChange). — 기존 useAuth의 구독 로직을 그대로 유지(코드 레벨 확인). 실제 구글 OAuth 로그인은 헤드리스 환경에서 재현 불가라 직접 클릭 테스트는 못함 — 사람이 브라우저에서 한 번 더 확인 권장.
  • ✅ pnpm build · pnpm lint가 통과한다. — 빌드 성공(청크 크기 경고는 기존 이슈, 무관), lint 0 error(기존 shadcn 파일의 warning 2건은 무관).
  • ✅ src/index.css에 포인트 색·--font-hand·participant 9색·브레이크포인트 토큰이 반영되고, index.html 구글 폰트 link에 Nanum Pen Script가 추가된다.
  • ✅ 브랜드 로고 SVG가 currentColor fill로 헤더에 적용된다.
  • ✅ design-tokens·book-agenda-view 두 스펙 문서의 hex 표기가 #E8412F로 갱신된다.

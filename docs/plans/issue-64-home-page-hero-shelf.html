1요약

현재 src/pages/Home/HomePage.tsx는 제목과 텍스트 링크만 있는 placeholder다. 이 작업은 PRD §7-1을 따라 히어로 책장(스티커 2장 포함), 떨어지는 글자(Glyph Drop) 물리 애니메이션, 날짜순 가로 책장(책등 펼침/카드 확장), 하단 장식 섹션을 구현한다. M0(#63, PR #67)에서 이미 병합된 브랜드 토큰(--font-hand, orange-500 #e8412f, participant-1..9)과 공통 셸(TheHeader, BrandLogo)은 재사용하고 다시 만들지 않는다. 데이터는 M3 완료 전까지 목업 17권을 쓰고, Club 상세(M5)는 아직 스펙이 없으므로 카드 클릭 이동 대상만 최소 placeholder로 채운다.

  • src/components/common/TheHeader.tsx, src/components/common/BrandLogo.tsx — M0에서 헤더(GNB)·모바일 탭바·로고 SVG 인라인이 이미 완성되어 있다. 이 이슈에서 재구현하지 않고 <TheHeader />만 마운트한다.

Glyph Drop에 필요한 초록·노랑·남색 3색만 이번 이슈에서 추가 토큰이 필요하다(§3 참고).

3설계

  • 글자 구성·색(OQ5) 확정 — PRD §11 OQ5는 미결이지만 권장안이 명시돼 있다 (docs/PRD.md:428): 히어로 4자 B U C K, 하단 3자 Z U C, 색은 point → 초록 → 노랑 → 남색 순환. 이번 작업에서 이 권장안을 채택해 진행한다(사용자 지정: "끝까지" 진행 승인). 색상 3종(#1f8a1f, #F2C400, #1d2a7a)은 기존 green-700/yellow-700과 값이 달라 --color-glyph-green / --color-glyph-yellow / --color-glyph-navy 3개 토큰을 src/index.css "point & 보조" 블록에 신규 등록한다(M0 재작업이 아니라 M1에서 새로 드러난 필요 — 컴포넌트에 생 hex를 쓰지 않는다는 §4 원칙을 지킨다).
  • 책 표지 스파인 색은 토큰 대상이 아니라 콘텐츠 데이터 — 브랜드 크롬(장식용 회색 책등·바닥선·스티커 등)은 반드시 neutral-*/orange-500/coral-300 토큰을 쓰지만, 가로 책장의 책별 스파인 색(프로토타입의 책마다 다른 hex)은 향후 books.cover_url(§8)로 대체될 콘텐츠 값이라 목업 데이터 파일 안에서만 hex를 허용한다. 컴포넌트 JSX 안에 인라인 hex를 직접 쓰지 않고 데이터에서 주입되는 값만 스타일에 바인딩한다.
  • Glyph Drop 컨테이너 스코프는 프로토타입과 동일하게 2단 — 히어로 레이어(4자)는 히어로 섹션과 가로 책장 섹션을 함께 감싸는 하나의 relative 박스 위에 절대 배치하고, 그 박스 내부의 모든 data-ob(책등)·data-floor(바닥선)를 충돌 대상으로 삼는다 (프로토타입 heroRef가 <main> 전체를 감싸는 것과 동일한 이유: 글자가 히어로 책등뿐 아니라 가로 책장 책등에도 튕겨야 함). 하단 레이어(3자)는 하단 장식 섹션만 감싸는 별도 박스이며, 실제 data-floor 요소 없이 박스 하단 자체를 합성 바닥으로 쓴다(프로토타입 bottomRef + floorY = cr.height 동일 이식).
  • 물리 로직은 range를 그대로 이식 — 중력 0.55/프레임(정규화 dt 기준), 책등 충돌 시 수평 이탈(6회 초과 시 front=true로 앞으로 빼서 계속 낙하), 바닥선에서 vy·vx·vr 감쇠 후 정지, 화면 밖(위/좌/우로 크게 벗어남)이면 제거. requestAnimationFrame 단일 루프, 프레임마다 getBoundingClientRect()로 재계산해 스크롤 중에도 좌표가 어긋나지 않게 한다(가로 책장 스크롤이 히어로 레이어 박스 안에 있으므로 특히 중요). prefers-reduced-motion: reduce면 낙하를 건너뛰고 바로 바닥 위치 + ±3° 고정 회전으로 배치한다(matchMedia 체크, 애니메이션 훅과 별개로 판정).
  • 히어로 반응형 스케일은 CSS로 불연속 재현 — PRD 공식 cw≥1100 ? 1 : clamp(0.55, (cw-40)/760, 0.85)를 scale(clamp(0.55, calc((100vw - 40px) / 760), 0.85)) 기본 + desktop: (≥1100px)에서 scale(1) 오버라이드로 구현해 JS 리사이즈 리스너 없이 처리한다. 1099→1100px 경계에서 0.85→1.0으로 점프하는 것은 프로토타입과 동일한 의도된 동작이다.
  • 가로 책장 펼침/이동은 클릭 2단(expand → direct) — PRD·완료 조건 문구("책등 클릭 → 카드 펼침 → 카드 클릭 → Club")를 그대로 따라 clickBehavior=expand 동작만 구현한다(프로토타입의 direct 모드는 이식하지 않음 — 옵션으로 노출할 필요가 없는 확정 동작). 펼침 시 가로 스크롤 컨테이너를 카드가 중앙에 오도록, 세로는 카드가 뷰포트 안에 들어오도록 스크롤(프로토타입 480행 로직 이식).
  • Club 상세는 placeholder 1개만 추가 — M5(#는 별도 이슈)에서 다룰 범위지만, 카드 클릭 이동 없이는 완료 조건을 검증할 수 없다. 기존 BookAgendaPage·MyPage와 동일한 얇은 placeholder 패턴(TheHeader + 제목 + TODO 주석)으로 src/pages/Club/ClubPage.tsx를 추가하고 /clubs/:clubId 라우트만 연결한다. Club 페이지 자체 설계는 이 이슈의 범위가 아니다.
  • 1440 컨테이너 테두리는 Home 로컬 스코프 — PRD §4-5의 "max 1440 중앙 정렬 + `0 0 0 1px #eee` 테두리"는 사이트 공통 셸을 새로 만들 근거가 아직 없으므로(다른 페이지는 모두 placeholder) 이번 이슈에서는 HomePage의 <main> 래퍼에만 max-w-(--width-shell) mx-auto + 테두리를 적용한다. 다른 페이지 공통화는 필요 시 후속 이슈로 분리한다.
  • 로딩/빈/에러 상태는 목업 페칭 훅으로 표현 — useHomeClubs() 훅이 {status:'loading'|'success'|'empty'|'error', data}를 반환하도록 만들고, 목업 구현은 짧은 지연 후 항상 success로 17권을 반환한다. 빈/에러 상태 UI는 실제로 만들어 두되, M1 시점엔 자연 발생하지 않으므로 테스트는 목업 배열을 일시적으로 비우거나 상태를 강제해 수동 확인한다(§6 테스트 계획). M3에서 Supabase 훅으로 교체될 때 이 상태 계약을 그대로 따른다.

5리스크

리스크영향완화책
rAF 물리 루프가 스크롤/리사이즈와 겹치며 프레임마다 다수의 getBoundingClientRect() 호출 → 저사양 기기에서 버벅임 LCP·체감 성능 저하 화면 밖 요소 즉시 제거, 정지(resting)한 글자는 매 프레임 재계산 대상에서 제외, 필요 시 requestIdleCallback 없이도 단일 루프 유지로 충분한지 실기기(또는 Chrome throttling)로 확인
OQ5(글자 구성·색)가 PRD상 공식 미결 상태에서 권장안으로 진행 디자인 승인 후 값이 바뀌면 재작업 필요 글자·색 배열을 letters.ts 한 파일에 격리해 변경 비용을 최소화, 플랜에 채택 근거 명시
가로 책장 카드 클릭이 가리키는 /clubs/:clubId가 아직 실제 페이지 없음(M5 미착수) 완료 조건 "카드 클릭 → Club 이동"을 검증할 수 없음 기존 placeholder 패턴과 동일한 최소 Club 페이지 1개만 추가, 본설계는 M5에서 별도 진행
목업 책 스파인 색(콘텐츠 hex)과 "컴포넌트에 생 hex 금지" 브랜드 원칙이 표면적으로 충돌 리뷰 시 오해 소지 플랜에 데이터-vs-브랜드크롬 구분 근거를 명시하고, 실제 hex는 데이터 파일에만 존재하도록 구현(컴포넌트는 데이터가 주는 값을 바인딩만 함)
히어로 scale 공식이 1099→1100px 경계에서 불연속 점프 일부 뷰포트에서 어색해 보일 수 있음(프로토타입 의도) 프로토타입과 동일 동작임을 플랜에 명시, QA 체크리스트에 720/1099/1100/1200 경계값 포함

6테스트 계획

  • pnpm build, pnpm lint 통과 확인.
  • 데스크톱 1440px — 헤더 로고 노출, 히어로 스티커 발제 클릭 시 가로 책장 섹션으로 부드럽게 스크롤, 책장 클릭 시 /bookshelf 이동.
  • 1200px(wide) — 히어로 우측 코랄/회색 책등 묶음과 바닥선 2분할(260px 간격) 노출 확인.
  • 1100~1199px(desktop, wide 아님) — 히어로 원본 크기(scale 1), 우측 묶음 숨김.
  • 720~1099px(compact) — 히어로가 0.55~0.85 사이로 축소되는지, 720px 근접값에서 nav가 탭바로 전환되는 경계와 겹치지 않는지 확인.
  • 390px(mobile) — 카드가 세로 배치(300×auto, 커버 상단 180px), 히어로 최소 축소, 하단 탭바 노출, 가로 책장 간격 40/최소 높이 380 적용 확인.
  • Glyph Drop — 히어로 4자 + 하단 3자가 낙하해 책등에서 옆으로 튕기고 바닥선에서 ±3° 내로 정지하는지, 책등 사이에 여러 번 끼면 앞으로 빠져나와 계속 떨어지는지, 화면 밖으로 나간 글자가 제거되는지 육안 확인.
  • DevTools에서 prefers-reduced-motion: reduce 에뮬레이트 후 재진입 — 글자가 애니메이션 없이 최종 위치(바닥, ±3° 고정)에 바로 놓이는지 확인.
  • 책등 클릭 → 카드 펼침(가로 중앙 + 세로 화면 안 스크롤) → 같은 카드 재클릭 → /clubs/:id placeholder로 이동 확인.
  • 좌우 원형 버튼 클릭 시 window.innerWidth*0.6만큼 부드럽게 스크롤되는지 확인.
  • 로딩 상태 — 훅의 지연 구간에서 책등 자리 스켈레톤 8개가 잠깐 보이는지 확인.
  • 빈 상태 — clubBooks.ts 배열을 임시로 비우고(커밋하지 않음) 점선 책등 1개 + "첫 모임을 등록해 보세요" 문구 노출 확인 후 원복.
  • 에러 상태 — 훅 내부에서 일시적으로 status:'error'를 강제해(커밋하지 않음) 인라인 에러 메시지 + 다시 시도 버튼이 뜨고, 클릭 시 재조회되는지 확인 후 원복.
  • 회귀 확인 — 헤더 로그인/로그아웃, 헤더 nav 활성 표시, 모바일 탭바가 기존과 동일하게 동작하는지(이번 변경으로 TheHeader를 건드리지 않으므로 회귀 없어야 함).
